理解这三代，可以先抓住三条主线：Qwen2.5 扩大文本预训练并完善指令能力；Qwen3 加强推理训练，公开 Dense 与 MoE 主力模型；Qwen3.5 强调统一视觉语言基座与高效混合注意力。

系列导航：[01 Transformer 与 ViT](/notes/llm-foundations-01-transformer-vit/) → [02 线性注意力](/notes/llm-foundations-02-linear-attention/) → [03 多模态架构与训练](/notes/llm-foundations-03-multimodal-training/) → **04 Qwen 三代对比**。

## 1. 先约定比较范围

资料核对日期：2026-10-06。本文比较 Qwen2.5 通用开放权重文本系列、Qwen3 首发文本系列，以及 Qwen3.5 的已公开代表模型；讨论视觉时，单独标明 Qwen2.5-VL 和 Qwen3-VL。

Qwen3 首发、Qwen3 后续更新、Qwen3-Next 和 Qwen3-VL 不是同一份配置。本文不是所有衍生型号的完整目录，也不把商业 API 的规格归入开放权重模型。参数量、上下文上限和推理模式最终都以具体权重版本为准。

## 2. 系列定位与数据

| 维度 | Qwen2.5 | Qwen3 | Qwen3.5 |
| --- | --- | --- | --- |
| 通用基座定位 | 文本 Causal LM | 文本 Causal LM，推理与通用能力融合 | 带视觉编码器的统一视觉语言基座 |
| 代表开放形态 | 通用文本主力为 Dense | Dense + MoE | Dense + MoE |
| 代表型号 | 7B、32B、72B | 8B、32B、30B-A3B、235B-A22B | Dense 27B；MoE 397B-A17B，另有其他尺寸 |
| 文本预训练量 | 最多约 18T token | 约 36T token | 本文所核对官方资料未给出可直接对比的精确总量 |
| 官方语言覆盖口径 | 29 种以上语言 | 119 种语言和方言 | 201 种语言和方言 |
| 数据演进 | 提升知识、代码、数学数据质量与覆盖 | 扩大多语言数据，结合文档提取及合成数据 | 强调视觉语言早期融合；精确模态配比未公开 |
| 视觉能力所在位置 | 由 Qwen2.5-VL 分支提供 | 由 Qwen3-VL 等分支提供 | 本文比较的基座本身支持视觉输入 |

这里的 T 是万亿。不同报告可能对文本 token、视觉 token、重复训练量采用不同统计口径，不能把数字简单相加。Qwen2.5-VL 报告的约 4.1T 训练 token，也不能当成其语言基座的 18T 文本预训练量。

依据：[Qwen2.5 发布说明](https://qwenlm.github.io/blog/qwen2.5/)、[Qwen3 发布说明](https://qwenlm.github.io/blog/qwen3/)、[Qwen3.5 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-397B-A17B)。

## 3. 预训练与后训练

| 维度 | Qwen2.5 | Qwen3 | Qwen3.5 |
| --- | --- | --- | --- |
| 预训练重点 | 大规模语言建模及高质量知识、代码、数学数据 | 通用预训练后提高知识密集型数据占比，再训练长上下文 | 视觉语言早期融合，结合高效主干 |
| 公开阶段信息 | 见技术报告中的预训练与长上下文扩展 | S1：30T+、4K；S2：约 5T，增强 STEM / 代码 / 推理；S3：扩展至 32K | 不能由模型卡还原完整逐阶段数据量、冻结策略和训练日程 |
| 监督微调 | 百万级指令样本 | 长 CoT 冷启动；后续进行模式融合 | 有后训练，但不能假定完整复用 Qwen3 的四阶段方案 |
| 偏好与强化学习 | 报告包含离线 DPO 和在线 RL | 推理 RL → 思考模式融合 → 通用 RL | 官方强调可扩展 RL、多任务和 Agent 环境 |
| 小模型能力迁移 | 不宜用单一配方概括全部型号 | 报告包含 strong-to-weak 蒸馏路线 | 各型号具体配方需单独查证 |
| 推理模式 | 通用 Instruct 不是统一双模式设计；专门推理模型另论 | 首发系列支持 Thinking / Non-thinking | 以具体模型卡和聊天模板为准，不照搬 Qwen3 开关行为 |
| 损失函数信息 | 文本预训练与后训练目标有公开说明 | 自回归目标及后训练目标，MoE 有负载均衡设计 | 各阶段完整损失组成与系数未全部公开 |

SFT 学习如何回答，偏好优化学习相对偏好，RL 则根据奖励改善行为；三者不是同一个训练步骤的不同叫法。Qwen2.5 报告把 DPO 放在 Offline RL 阶段，但 DPO 的实现并不需要像在线 RL 那样持续与环境交互采样。

Qwen3 的“混合思考模式”是回答行为与训练设计，不是“混合注意力”。前者涉及是否生成推理过程及推理预算；后者涉及主干层采用哪种信息混合机制。

依据：[Qwen2.5 技术报告](https://arxiv.org/html/2412.15115v2)、[Qwen3 技术报告](https://arxiv.org/html/2505.09388v1)。

## 4. 文本主干与注意力

| 维度 | Qwen2.5 通用文本 | Qwen3 首发文本 | Qwen3.5 代表模型 |
| --- | --- | --- | --- |
| 主干 | Decoder-only Transformer | Decoder-only Transformer | 混合注意力的自回归主干 |
| 注意力 | 标准因果注意力 + GQA | 标准因果注意力 + GQA | Gated DeltaNet 与 Gated Full Attention 交替 |
| 位置与归一化 | RoPE、RMSNorm | RoPE、RMSNorm，并引入 QK-Norm | 全注意力及视觉位置配置按具体模型查看 |
| QKV bias | 使用 | 移除 | 所核对配置中 attention_bias 为 false |
| FFN | 通用开放文本型号为 Dense，使用 SwiGLU | Dense FFN 或稀疏 MoE | Dense FFN 或稀疏 MoE |
| 全注意力层比例 | 主干注意力层均为全注意力 | 首发主干注意力层均为全注意力 | 所核对 27B / 397B 配置为每 4 层 1 层全注意力 |
| 历史缓存 | 各全注意力层保留 KV | 同左，GQA 减少 KV 头数 | 线性层维护状态，全注意力层仍保留 KV |

Qwen3.5 的路线与 Qwen3-Next 的混合架构相关，但不能把“架构沿用”理解成直接继承同一份已训练权重，也不能把 Qwen3 首发文本模型写成 Gated DeltaNet 主干。

Dense 只描述参数使用方式，并不意味着必须采用标准注意力。Qwen3.5-27B 是 Dense，但其配置同样包含线性注意力与全注意力。[27B 官方配置](https://huggingface.co/Qwen/Qwen3.5-27B/blob/main/config.json)

## 5. MoE：系列共性与具体数字

| 项目 | Qwen2.5 通用开放文本系列 | Qwen3-235B-A22B | Qwen3.5-397B-A17B |
| --- | --- | --- | --- |
| 架构形态 | 主力开放型号为 Dense | MoE | MoE |
| 总参数 / 激活参数 | Dense 不使用稀疏专家选择 | 约 235B / 22B | 约 397B / 17B |
| 路由专家数 | 不适用 | 128 | 512 |
| 每 token 激活的路由专家 | 不适用 | 8 | 10 |
| 共享专家 | 不适用 | 无共享专家 | 1 个 |

Qwen2.5 技术报告也讨论了 MoE，因此“Qwen2.5 完全没有 MoE”不准确；这里限定的是通用开放权重文本主力型号。

MoE 通常替换块中的 FFN，而不是把注意力也变成专家路由。不同 token 可以选择不同专家。共享专家按设计持续参与，路由专家由路由器选择。

“397B 总参数、17B 激活”意味着每 token 只使用部分参数进行计算，不意味着权重存储只需容纳 17B。粗略估算，397B 权重若全部用 2 字节存储，约需 794 GB 的纯权重空间；量化、分片和卸载会改变部署方式，而 KV Cache、递推状态和运行时工作区还需额外空间。这是算术估算，不是可直接照搬的单机显存配置。

依据：[Qwen3 架构说明](https://arxiv.org/html/2505.09388v1#S2)、[Qwen3.5-397B-A17B 模型卡](https://huggingface.co/Qwen/Qwen3.5-397B-A17B)。

## 6. 397B-A17B 的注意力配置，不能推广到所有尺寸

| 配置项 | Qwen3.5-397B-A17B |
| --- | --- |
| 语言主干隐藏维度 | 4,096 |
| 语言主干层数 | 60，15 个重复块 |
| 每块注意力布局 | 3 个 Gated DeltaNet + 1 个 Gated Attention |
| 线性注意力头 | 16 个 QK 头、64 个 V 头，头维度 128 |
| 标准门控注意力头 | 32 个 Q 头、2 个 KV 头，头维度 256 |
| RoPE 旋转维度 | 64，不能误认为完整注意力头维度 |
| MoE 专家中间维度 | 1,024 |
| 填充后的词表相关维度 | 248,320 |

特别需要校正两个容易传播的错误：**不是 2 个 Q 头、2 个 KV 头；248,320 也不是隐藏维度。** 对该型号，输入 Embedding 的形状应从词表大小和隐藏维度两个轴理解。

60 层和上表中的头数都属于这个具体型号。不同大小模型的层数、宽度和专家配置必须分别查阅。[397B 官方配置](https://huggingface.co/Qwen/Qwen3.5-397B-A17B/blob/main/config.json)

## 7. 多模态路线：Qwen2.5-VL → Qwen3-VL → Qwen3.5

| 维度 | Qwen2.5-VL | Qwen3-VL | Qwen3.5 |
| --- | --- | --- | --- |
| 基础组成 | ViT + MLP Merger + Qwen2.5 语言主干 | ViT、视觉合并与语言主干，加入多层特征融合 | 视觉编码器、视觉合并与混合注意力语言主干 |
| 视觉处理 | 动态分辨率；视觉端窗口注意力与少量全注意力 | 加强多层视觉表示的利用 | 具体视觉配置按型号查看 |
| 深层视觉注入 | 不采用 Qwen3-VL 的 DeepStack 路线 | DeepStack 将多层视觉特征注入语言模型 | 所核对 397B 配置的 deepstack_visual_indexes 为空 |
| 空间与时间 | MRoPE；时间维与绝对时间对齐 | Interleaved-MRoPE、文本时间戳对齐 | 不能仅凭系列名推断与前代每个位置编码细节完全相同 |
| 训练关系 | 从文本基座初始化，再经历对齐与联合训练 | 独立 VL 分支，不能概括成只训练连接器 | 官方强调统一视觉语言基座和早期融合 |

“去掉 DeepStack”不等于没有视觉特征融合；图片仍经过视觉编码和合并进入 LLM。“原生多模态”也不等于旧版本从未联合训练。详细解释见[第三篇的训练阶段与损失分析](/notes/llm-foundations-03-multimodal-training/)。

依据：[Qwen2.5-VL 报告](https://arxiv.org/html/2502.13923v1)、[Qwen3-VL 模型卡](https://huggingface.co/Qwen/Qwen3-VL-30B-A3B-Instruct)、[Qwen3.5 配置](https://huggingface.co/Qwen/Qwen3.5-397B-A17B/blob/main/config.json)。

## 8. 上下文与生成效率

| 项目 | Qwen2.5 | Qwen3 | Qwen3.5 |
| --- | --- | --- | --- |
| 常见文本上下文口径 | 型号与配置不同，常见 32K / 128K | 首发训练扩展至 32K，部分型号通过 YaRN 支持约 128K | 397B 官方标注原生 262,144 |
| 百万上下文 | 专门的 Qwen2.5-1M 变体，不能代表全系列 | Qwen3-VL / 后续版本不能与首发文本系列混用 | 397B 可扩展至约 1,010,000 |
| 注意力效率 | GQA 及高效全注意力内核 | 同类优化，MoE 降低部分 FFN 计算 | 混合线性 / 全注意力，MoE 型号结合稀疏计算 |
| 多 token 预测 | 不作为通用系列共同特征 | 不把后续分支特征套到首发全部型号 | 397B 官方列出多步 MTP 训练 |

这里必须区分训练长度、配置支持长度、位置外推后的长度，以及特定服务开放的长度。能接收百万 token 不代表在任意位置都能保持相同召回精度，也不代表可以输出百万 token。[Qwen2.5-1M 技术报告](https://arxiv.org/abs/2501.15383)

MTP（Multi-Token Prediction）通过额外预测未来多个位置来训练相关能力，并可支持投机解码。实际加速需要推理引擎支持候选生成、验证与接受机制，收益取决于接受率和系统开销。它不是“一次前向随意输出多个未经验证的最终 token”。

混合注意力降低大量层的长上下文开销，但仍有全注意力层；因此整体成本不能一概写成 O(N)，缓存也不能一概写成与 N 无关。

## 9. 如何公平比较三代？

| 常见比较错误 | 更合理的做法 |
| --- | --- |
| 小模型开长思考，大模型直接答，然后说前者全面更强 | 记录推理预算、输出长度、采样次数和评分方法 |
| 只比较总参数量 | 同时看激活参数、精度、延迟、吞吐和总部署内存 |
| 用一个型号代表整个系列 | 固定完整模型 ID、版本和聊天模板 |
| 把图片问答结果等同于完整多模态能力 | 分别检查 OCR、图表、空间、视频和纯文本任务 |
| 把未公开数据写成确定数字 | 标注信息缺口，保留官方来源 |

读配置时先看架构和训练事实，再看同条件评测。三代的差异来自数据、优化、后训练、模型规模和系统工程的共同变化，不能把所有提升归因于单一注意力模块，也不能把“原生多模态”直接当成效果保证。
