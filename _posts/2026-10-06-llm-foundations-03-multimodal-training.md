关于多模态，最容易混淆的是三件事：模型由哪些模块组成、模块从什么权重初始化、训练时哪些参数一起更新。这三个问题必须分开回答。

## 1. 多模态大模型有哪些路线？

多模态是能力范围，不是一种唯一架构。下表用于建立技术地图，并非当前产品排行榜或完整型号目录。

| 路线与代表 | 如何连接模态 | 需要注意的边界 |
| --- | --- | --- |
| CLIP | 图像、文本分别编码，通过对比目标对齐 | 本身不等于生成式聊天模型 |
| BLIP-2 | 冻结的视觉编码器与 LLM 之间加入 Q-Former | 用可学习 Query 提取适合语言端的视觉信息 |
| Flamingo | Perceiver Resampler 整理视觉特征，通过门控 Cross-Attention 接入语言模型 | 不同于直接把所有视觉 token 拼到文本前面 |
| LLaVA | 视觉编码器 + Projector + 自回归 LLM | 核心路线简洁；不同版本的分辨率、数据和训练策略有变化 |
| Qwen2.5-VL / Qwen3-VL | ViT、视觉特征合并及语言主干 | 进一步处理动态分辨率、空间位置和视频时间信息 |
| Qwen3.5 | 带视觉编码器的统一视觉语言基座 | 强调多模态早期融合，仍保留视觉编码器 |

更广义的多模态模型还可能支持音频输入、语音输出或图像生成。**能理解图片不代表能生成图片，能接收视频不代表也能处理其中的音轨。** 必须查看具体模型支持的输入输出模态。

架构来源：[BLIP-2](https://arxiv.org/abs/2301.12597)、[Flamingo](https://arxiv.org/abs/2204.14198)、[LLaVA](https://github.com/haotian-liu/LLaVA)、[Qwen3-VL](https://huggingface.co/Qwen/Qwen3-VL-30B-A3B-Instruct)。

## 2. LLaVA 的架构是什么？

以经典 LLaVA / LLaVA-1.5 路线为例：

```text
图片 → CLIP 视觉编码器 → patch 特征 → Projector ─┐
                                              ├→ 拼接输入序列
问题 → Tokenizer → 文本 Embedding ─────────────┘
                                                   ↓
                                              自回归 LLM
                                                   ↓
                                               文字回答
```

视觉编码器提取特征；Projector 把视觉特征映射到语言主干能够使用的表示空间；LLM 根据视觉 token、问题和已生成文字继续预测答案。

原始 LLaVA 使用线性投影；LLaVA-1.5 使用两层 MLP 连接器。不能把“只有一层线性层”当成整个 LLaVA 系列永远不变的定义。

连接器不必先生成图片描述，再交给 LLM。大多数这类前向路径直接传递连续视觉向量。视觉和文本信息可以在 LLM 的各层内部交互。

## 3. LLaVA 为什么分两个阶段训练？

| 阶段 | 视觉编码器 | Projector | LLM | 学习目标 |
| --- | --- | --- | --- | --- |
| 特征对齐 | 冻结 | 训练 | 冻结 | 把视觉表示变成语言端可利用的输入 |
| 视觉指令微调 | 经典配置中继续冻结 | 训练 | 训练 | 学会依照问题使用图像信息并生成答案 |

对齐阶段的连接器尚未适配 LLM，先限制更新范围有助于减少对已有能力的扰动。第二阶段让语言模型一起适应图像条件下的指令和对话。这是经典配置，不代表后续 LLaVA 变体都必须冻结视觉编码器。[LLaVA 官方训练说明](https://github.com/haotian-liu/LLaVA#train)

“冻结”指不更新该模块权重，不意味着它不执行前向计算。冻结 LLM、训练它前面的连接器时，通常仍需让梯度穿过 LLM 返回连接器；不能简单把整个 LLM 的前向包进 `no_grad()`，否则会切断这条训练路径。

## 4. 文本和 VL 以前真的一直分开训练吗？

不是。需要区分三个说法：

| 说法 | 准确含义 |
| --- | --- |
| 文本与 VL 分开发布 | 权重和产品定位不同，不代表内部没有联合训练 |
| 视觉和语言分别预训练 | 初始化阶段分别获得视觉表示、语言能力，之后可以联合优化 |
| 视觉和语言始终独立训练 | 是更强的限制，不是过去所有 VL 模型的共同特点 |

Qwen2.5-VL 就使用预训练 Qwen2.5 初始化语言部分，视觉部分另行预训练；随后先对齐视觉部分，再解冻全部参数做多模态训练，接着训练长上下文。因此，不能把它描述成“两个模型各学各的，最后接起来就结束”。[Qwen2.5-VL 技术报告 §2.2.2](https://arxiv.org/html/2502.13923v1#S2.SS2.SSS2)

## 5. 为什么过去常先训练文本，再扩展 VL？

这是成本、数据和稳定性之间很实用的折中：

1. **复用语言基座。** 大规模文本预训练已经积累语言、知识、代码和推理能力，接入视觉时不必全部重学。
2. **适应不同的数据条件。** 图片数量多，不等于有足够准确、细致且与图片对应的监督。图表、OCR、视频推理数据需要额外加工。
3. **控制计算预算。** 图像需要视觉编码，视频还会产生大量视觉 token；分阶段引入便于管理成本。
4. **降低优化难度。** 刚初始化的连接器输出不稳定，先对齐再联合优化，更容易控制对语言表示的扰动。
5. **支持独立迭代。** 同一个文本基座可以连接不同视觉编码器，也能继续用于纯文本应用。

多模态训练还可能导致纯文本能力退化。VILA 的研究发现，在视觉指令微调中混回文本指令数据，能缓解这类退化，并改善其视觉语言任务表现。这是特定研究的结果，不能据此推断任意数据混合比例都有效。[VILA 论文](https://arxiv.org/abs/2312.07533)

## 6. “原生多模态”改变了什么？

这个术语没有完全统一的边界。在这里，重点是多模态更早、更充分地参与基础模型能力的形成。Qwen3.5 官方使用的是对多模态 token 进行早期融合训练的表述。[Qwen3.5 官方模型卡](https://huggingface.co/Qwen/Qwen3.5-397B-A17B)

它不自动意味着以下任何一项：

- 取消 ViT，直接让文本 LLM 接收原始像素。
- 所有权重从随机初始化开始，同一步一起训练。
- 全程不冻结参数、不分阶段、不调整数据比例。
- 必须预测像素、重建图像，或支持图片生成。
- 旧 VL 从未进行过多模态预训练或全参数联合训练。

“早期融合”也可能用来描述架构中的融合位置，所以读报告时要进一步看：它究竟指输入表示如何融合，还是视觉何时加入基础训练。仅凭宣传标签无法还原完整训练日程。

## 7. 为什么现在更有条件做？

| 条件 | 改善带来的作用 | 仍需解决的问题 |
| --- | --- | --- |
| 更成熟的数据生产与筛选 | 用已有模型辅助 OCR、详细描述、问题合成，再过滤和验证 | 合成内容可能幻觉，错误不能反复放大 |
| 更成熟的混合训练配方 | 调整文本与视觉任务采样、学习率和课程顺序 | 模态干扰和语言能力退化仍可能发生 |
| 更高效的视觉表示与主干 | 压缩 token、优化注意力和稀疏计算 | 细节损失、缓存和通信开销仍存在 |
| 更好的训练调度 | 对不等长图片、视频和文本进行打包与负载均衡 | 不同任务的计算形状仍不完全相同 |
| 更明确的应用需求 | 文档、界面操作和视频推理需要持续图文协同 | 统一基座是否更好必须经过实际评测 |

这是对行业演进的解释，不是 Qwen3.5 完整配方的复述。官方强调多模态训练效率接近纯文本，但这不能解释成视觉计算“免费”，更不意味着相同样本数下成本完全相同。

## 8. “视觉损失”和“文本损失”怎么区分？

**损失按训练任务定义，不能只按输入模态命名。** 输入含图片，损失仍然可以是文本 token 的交叉熵。

| 任务 | 模型预测什么 | 典型损失 | 参数可能更新到哪里 |
| --- | --- | --- | --- |
| 自回归文本建模 | 下一个文字 token | token 交叉熵 | 文本主干和输出层 |
| 图像分类 | 类别分布 | 类别交叉熵 | 视觉编码器和分类头 |
| CLIP 图文对齐 | 哪张图匹配哪段文字 | 双向对比损失 | 图像、文本编码器 |
| MAE 图像重建 | 被遮住的像素块 | 重建误差，如 MSE | 视觉 Encoder 和重建 Decoder |
| 视觉问答 | 给定图像和问题后的答案 token | 条件文本交叉熵 | LLM、连接器及未冻结的视觉编码器 |
| 扩散式图像生成 | 噪声、速度或其他训练目标 | 对应参数化下的回归目标 | 图像生成网络等模块 |

视觉问答的简化目标是：

```text
L_answer = - sum_t log p(y_t | image, question, y_<t)
```

例如输入一张图表，问“第二季度是多少”，监督答案为“120 万元”。训练通常在答案位置计算交叉熵，问题和视觉输入作为条件。具体哪些 token 参与 loss，由训练样本的 label mask 决定。

## 9. 没有像素重建损失，为什么 ViT 也能学？

因为端到端可微的路径允许答案误差反向传播：

```text
前向：图像 → ViT → Merger → LLM → 答案概率
反向：图像 ← ViT ← Merger ← LLM ← 答案交叉熵
```

如果答案预测错误，梯度会告诉可训练模块怎样改变表示，才能提高正确答案的概率。损失的监督对象是文字，但它能间接训练视觉特征。

能否更新 ViT 取决于它是否被冻结、计算图是否被 detach、优化器是否包含其参数。并不是“图像经过模型”就必然训练到了视觉编码器。

因此不能未经报告支持就写成 `L_total = L_text + L_image`。有的阶段只有条件文本损失，有的阶段加入对比、重建或辅助损失；MoE 还可能包含路由相关目标。Qwen3.5 未公开的各阶段损失权重和数据配比，应当保留为未公开。
